# PawPal — E2E Test & Feature Audit (2026-07-17)

Scope: every mobile flow driven live on the Android emulator (Pixel_3, dev build `com.pawpal.app`) against the local backend (Spring Boot 4, Postgres/Redis/Kafka via docker-compose), plus API-level tests where UI automation was impractical. Test data was created under a throwaway account (`e2e.tester@pawpal.test`, user 602) and fully removed afterward.

### Known quirks (not fixed, low priority)

## 2. What's remaining (not implemented / gaps ⏳)

1. **No real unit tests.** The backend suite is a single context-load smoke test (`PetSocialApplicationTests`); the frontend has no test runner configured at all. The auth, board, and matching logic have zero coverage. This audit was manual E2E — nothing guards regressions.
2. **Posts / Friends / Comments / Events have no API.** Entities exist (`Post`, `Comment`, `Friendship`, `Event`, `EventAttendee`) and the Me tab shows Posts/Friends counts (always 0), but there are no controllers to create or read them. Either build the endpoints or drop the entities + stat tiles.
3. **The app never sends location telemetry.** `POST /api/telemetry/location` (Kafka → Redis `users:geo`) is only fed by the test-data generator/demo scripts. Consequently `users:geo` reflects synthetic data, and the "online" dot comes from the account-active flag, not presence. Wire a periodic ping from the app (or explicitly declare the telemetry pipeline demo-only).
4. **Host-side accept/deny not E2E-verified.** `PUT /api/walk|date/requests/{id}` is wired in `NotificationDetailScreen`, but testing it needs a second interactive login (host account). Worth a two-device/two-account pass.
5. **Reviews**: `ReviewController` + `Review` entity exist but no screen calls them; pet `rating` is displayed from the pet row instead.
6. **Password reset ("Forgot password?") is a dead link**; no backend endpoint exists.
7. **Photo upload** (profile/pet/market) — UI buttons exist, no storage backend; `avatarUrl`/`photoUrl` only populated via Google sign-in or seed data.
8. **Market chat E2E** — `/api/market/chats` + market-item threads work at the API level; buyer↔seller UI flow needs a two-account pass.

## 3. What looks obsolete (candidates to remove 🗑)

Parallel/legacy backend surfaces with **no frontend callers** (verified by grepping every `api*` call in `frontend/mobile/src`):

| Surface | Superseded by | Note |
|---|---|---|
| `InvitationController` (`/api/invitations`, Event-based join flow) | `/api/walk|date/invitations` (partner_invitations) | Old generic invitation system on the `events` table |
| `MarketplaceController` (`/api/marketplace/items`) | `MarketController` (`/api/market`) | Old marketplace API shape |
| `MatchController` (`/api/matches`) + `PetMatch` entity | Blind-date request flow | Match lifecycle (accept/deny/block) unused |
| `MatchingController` (`/api/match`) + `MatchingService` | — | Redis geo matching PoC; app never calls it |
| `NotificationController` (`/api/notifications` generic CRUD) | `/api/walk|date/notifications` | Table is still written by board flows — keep the writes, the generic REST surface is unused |
| `UserController` (`/api/users/register|login`, `/api/users/{id}`) | `/api/auth/*`, `/api/users/me` | Explicitly kept as backward-compat aliases; app no longer uses them |
| `PetQueryService` trio (`/api/pets/nearby|partners|blind-dates`) | walk/date feeds | Depends on Redis geo data the app never produces |
| `frontend1/` directory | `frontend/` | Old mapping reference (per project notes) — exclude from any prod build |
| Legacy SHA-256 password path in `AuthService` | BCrypt | Keep until no `password_hash` without `$2` prefix remains, then delete |
| `mockData.ts` in the mobile app | live API | Only referenced by screens as fallbacks/types now |

Internal tooling (keep, but not product code): `DashboardController` (`/dashboard` Thymeleaf), `InspectorController`, `TestDataController`, `HealthController`.

## 4. Environment runbook (for repeating this)

- Emulator: `emulator.exe -avd Pixel_3 -dns-server 8.8.8.8,1.1.1.1`, then `adb reverse tcp:8081 tcp:8081` (Metro on host).
- Backend: IntelliJ run config or `MGMT_ENDPOINTS=health,info,prometheus MGMT_PROMETHEUS_ENABLED=true ./mvnw spring-boot:run` (without those env vars the Prometheus scrape 500s).
- Verified test suite passes: `./mvnw test` (1 test).
